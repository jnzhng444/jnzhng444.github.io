PROJECT / 01COMPILERS / RISC PROCESSOR SYSTEMS2026

From code to a RISC system.

Custom Compiler and RISC Processor System

An integrated language, compiler, and processor project targeting the custom Craft21 architecture. Programs travel from source code through compiler optimizations to a five-stage RISC pipeline with L1/L2 caches.

MY CONTRIBUTION

My team and I co-designed the language and built the complete compiler: lexical, syntactic, and semantic analysis, IR, code generation, optimizations, tests, and metrics. I also contributed to integration with the RISC pipeline and cache hierarchy.

  • Python
  • IR & CFG
  • Craft21 / Custom RISC ISA
  • Compiler optimization
  • SystemVerilog integration
Under the hood +

The compiler implements loop unrolling, liveness-based dead code elimination, register renaming, and dependency-aware instruction scheduling. We evaluated correctness and optimization impact through code size, instruction counts, compilation time, and simulated execution cycles. The processor is implemented in SystemVerilog; my main contribution was the compiler, with a smaller role in processor integration rather than primary ownership of its architecture.

PROJECT / 02EMBEDDED / REAL-TIME SYSTEMS2026

The right task. On time.

Heterogeneous Real-Time Scheduling System

Coordinating periodic and sporadic work across a Linux host, an ESP32, and a Raspberry Pi Pico H, with deadlines as a first-class constraint.

MY CONTRIBUTION

Contributed to the team system spanning RMS/EDF scheduling, node calibration, First-Fit/Worst-Fit allocation, schedulability checks, and deadline monitoring.

  • C / C++
  • Linux & POSIX
  • ESP32 / Pico H
  • Serial & CRC
Under the hood +

The host coordinates heterogeneous nodes over CRC-validated serial messages. Host processes communicate using POSIX shared memory and semaphores. The project includes calibration, admission, allocation, monitoring, and reports. The browser demo isolates single-CPU scheduling to explain priorities; it does not emulate the hardware or distributed system.

PROJECT / 04CRYPTOGRAPHY / RISC-V ASSEMBLY

Small instructions. A stream of bits.

ChaCha20 on RISC-V

A bare-metal implementation of the ChaCha20 stream cipher in RV32IM assembly. A C harness connects the low-level routines to RFC 8439 test vectors, with QEMU and GDB providing an inspectable execution environment.

MY CONTRIBUTION

Participated in the implementation and testing work published in my ChaCha20 repository, connecting assembly routines with a C test harness and a bare-metal debugging workflow.

  • RV32IM assembly
  • C
  • QEMU
  • GDB
  • Docker
Under the hood +

The code separates the quarter-round, inner block, block generation, and encryption routines. Addition, XOR, and rotation mix a 16-word state into a keystream that is XORed with the input. The repository includes RFC test vectors; this portfolio does not execute the cipher or claim production security or sole authorship of every component.

PROJECT / 05MEMORY / DATA STRUCTURES

Follow the references.

MPointer — Managed Pointers in C++

A C++17 library exploring managed pointers, reference counting, and a collector. Doubly linked lists and sorting algorithms put the memory model to work beyond isolated pointer examples.

MY CONTRIBUTION

Participated in the MPointer library project, working with a C++ codebase that connects managed pointers and reference tracking with reusable data structures and Google Test suites.

  • C++17
  • Reference counting
  • CMake
  • Google Test
Under the hood +

MPointer wraps a managed allocation while MPointerGC tracks references. Copying and releasing references changes whether an allocation remains reachable through these pointers. The repository also includes doubly linked lists, Bubble Sort, Insertion Sort, and Quick Sort. The diagram illustrates reference counting; it is not a live memory trace or a claim that reference cycles are collected.

From logic gates to a pipeline.

Computer Architecture Foundations — FPGA & RISC-V

Two projects from Computer Architecture Foundations: a 4-bit ALU on an FPGA communicating with a Raspberry Pi Pico W over SPI, and a Python desktop simulator for a five-stage RISC-V pipeline.

MY CONTRIBUTION

Participated in the collaborative architecture coursework, exploring digital logic, FPGA integration, serial communication, and processor simulation. This is a separate project from the Craft21 compiler and processor system.

  • SystemVerilog
  • FPGA / Quartus
  • SPI / MicroPython
  • Python / PySide6
  • RISC-V
Under the hood +

The FPGA study combines arithmetic operations, serial operand input, LEDs, seven-segment displays, and PWM. The simulator models IF, ID, EX, MEM, and WB, with forwarding, load-use stalls, and branch flushes. It supports an educational subset of RISC-V, uses symbolic instructions and Python integers, and does not claim complete ISA conformance or a physical RISC-V processor implementation.

PROJECT / 08PROGRAMMING PARADIGMS / NETWORKED GAME

Two languages. One game loop.

Tarea4Paradigmas — Donkey Kong Jr. in C + Java

An academic platform game inspired by Donkey Kong Jr., combining a C/raylib graphical client with a Java server. TCP messages connect player input, game simulation, and spectators watching a room.

MY CONTRIBUTION

Project work in programming paradigms, connecting a procedural C client with an object-oriented Java server. The repository brings together graphics, networking, game rules, and event-driven state updates.

  • C99 / raylib
  • Java / Swing
  • TCP / WinSock2
  • Observer / Factory
  • Concurrent game loops
Under the hood +

Each player has an independent game room; spectators receive its state without controlling the character. A scheduled server loop updates physics and entities, while the client renders the scene and sends movement commands. Goal detection occurs in the client and sends WIN to the server. An event bus distributes updates, a factory creates entities, and Swing or console controls administer the game. No individual module ownership or browser-playable version is claimed.
